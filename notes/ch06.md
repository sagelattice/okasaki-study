## Observations

### LazyBinomialHeap

- the `lazy pattern` idea above applies here; I misunderstood the syntax when translating from the book. the SML/NJ extension used by the book's code allows for `fun lazy ...` which suspends the application of the function. the pattern matching syntax + strict evaluation meant that the previous translation I wrote did not have the same amortized boundaries as the book. I fixed this by removing the eager forcing and moving the force within the suspensions
- I kept that syntax for `is_empty` because it needs to force the suspension to produce a value
- `find_min` and `delete_min` force $O(\log\ n)$ amortized costs, but `delete_min` defers re-merging the heap children, which suspends $O(\log\ n)$ cost
- I later reverted the syntax for `find_min` because it always forces, so the syntax is clearer


### PhysicistsQueue

- the theorem "The amortized costs of `snoc` and `tail` are at most two and four, respectively" and its proof are cool. the $O(n)$ rotation cost is amortized to $O(1)$ by lazy suspension of the rotation. $O(n)$ is paid in full over a sequence of operations but laziness and memoization make each incremental operation $O(1)$ amortized and support the assumptions of the physicist's method analysis. persistence would otherwise break the logical assumption and cause $O(n)$ to be paid repeatedly

### BottomUpMergeSort

- this example helped clarify things for me even further; each `add_seg` application encodes a segment for the position $2^i$ in `size`. the whole segment list encodes the (possibly) suspended binary digits. the "merge" binary carry operation is analogous to [binomial heaps referenced earlier in the book](ch03.md#binomial-heaps)
- sort is always eager and $O(n\ log\ n)$ because it forces the entire suspended segment list (the encoded binary number)
- this is applied version of the iterative vs monolithic deconstructive analysis presented in the book
- exercise 6.7 converting this lazy iterative pattern to a stream seems like it would translate simpler to Rust with iterators + ownership
